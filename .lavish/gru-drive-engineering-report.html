Engineering status report

GRU-Drive: where it stands, what is broken, what to do next

A private network drive that turns machines you already own (a Raspberry Pi, an old laptop) into a mounted Linux folder. The master speaks Network Block Device (NBD) to the kernel and fans each 4 KiB stripe out over UDP to a RAID10-style ring of minions.

Sources: docs/reviews/project-review-2026-07-03.md, project-review-2026-06-22.md, docs/known-issues.md, docs/architecture/roadmap.md, docs/current/step-order.txt, README, and the code at HEAD 13689e3 plus the uncommitted working tree as of 2026-09-08.

The one-paragraph verdict

The architecture is sound and the last review's four P1 crashes are genuinely fixed. But the RAID10 write path can still acknowledge a write to the kernel before the mirror copy is ever sent (N1), overlapping writes can land in any order (F4), and the failover machinery is unreachable because nothing ever marks a node down (N2). The roadmap says "persistent metadata next". This report recommends fixing those three first, because persisting placement and out-of-sync state is not worth much while the state it persists is wrong.

P1Do first

Register all children before any can complete

A mirrored write acks the kernel after replica 1 replies, then throws on replica 2. Silent partial write. One-day fix in MasterRuntime.
P1Do second

Add a range-ordering seam plus a write epoch

Two overlapping writes race through the pool, UDP, and the minion pool. A retransmit can resurrect old data. Introduce RangeSequencer.
P2Do third

Wire heartbeat-driven liveness

Read failover and degraded writes exist but every active flag is permanently true. A dead minion still takes the whole device down.

1. Architecture review

What the system is, how a request moves through it, and where the design is strong or thin. Diagrams first, evidence below each.

1.1 What does the user see, and what actually runs?

The user gets a normal mounted folder. Below it, Linux owns filesystem semantics and GRU-Drive owns only offsets, byte ranges, placement, and replication. That line was drawn deliberately.

1.2 How is the code layered?

Master and minion share nothing except the wire protocol. Both are thin concrete layers over a generic reactor-plus-thread-pool framework that knows nothing about storage. This is the project's best structural decision, and also the seam through which most of the P2 lifetime bugs leak.

Why it matters

Commands are looked up by integer key derived straight from wire::MessageType, so there is no second protocol vocabulary. Plugins can replace a command at runtime via inotify + dlopen without a restart.

Where it leaks

The factory takes no-argument creators (ICommand* (*)()), so commands cannot receive their runtime. Every master command calls GetActiveMasterRuntime(), a file-static pointer with no mutex (F8).

1.3 What happens to one 4 KiB write?

The kernel emits one write per block. The master resolves it to a primary and a mirror, sends two datagrams, waits for two replies, and only then acks the kernel. Three threads are involved on the master: the reactor thread, a pool worker, and (for retries) a timer thread.

Step 5 is where N1 lives: children are registered and sent one at a time, and step 9 completes the parent as soon as the child set is empty. Step 3 onwards is where F4 lives: nothing orders two overlapping requests. Both are detailed in the bug catalog.

1.4 Where does each block live?

RAID10 as a ring. The logical device is cut into 4 KiB stripes, striped across primaries, and every stripe is also written to the next node. Exposed capacity is the minimum node capacity times node count divided by two.

Strengths (keep these)

  • The NBD boundary is the right cut.

    Linux owns files and directories, GRU-Drive owns offsets. That is why the whole master fits in a handful of classes. Verified in concrete/master/src/NBDCommunicator.cpp.

  • Framework and concrete layers are genuinely separate.

    The framework has no storage vocabulary; command keys come from wire::MessageType. Master and minion reuse the same reactor, pool, and plugin loader.

  • The wire protocol was versioned on day one.

    A fixed 64-byte header with magic, version, type, status, UUID, flags, offset and lengths. Validation of reserved fields and payload bounds is tested in WireProtocolTest.

  • Retry is one small framework class.

    AsyncInjection reschedules itself every 100 ms and gives up after 10 rounds. Master commands just return PostTaskParams. Elegant, but see N8/N14 for the missing cancel handle.

  • The June P1 crashes were fixed properly, not patched.

    Sub-stripe capacity now throws a clean error with a regression test; NBD header reads use ReadAll; replies hold m_replyMutex across header and payload; single-minion metadata is per instance. All re-verified by reading the code.

  • Real concrete test coverage.

    15 test binaries under make test, including a smoke test that spawns a real minion process, all without root.

Weak points (what the rest of this report is about)

  • P1

    No ordering seam anywhere.

    Two overlapping writes go through a multi-worker pool, then UDP, then a second multi-worker pool on the minion, with no per-range lock at any of the five hops. F4

  • P1

    Completion predicate is "child set empty", but children are added one at a time.

    A fast reply to child 1 completes the parent before child 2 is registered. N1

  • P2

    Degraded mode is implemented but unreachable.

    SetNodeActive and SendHeartbeatRequest have zero non-test callers. Confirmed by grep on 2026-09-08. N2

  • P2

    Shutdown is a cluster of ordering races.

    Runtime is cleared before the pool stops (F8), plugins are unloaded before the pool drains (N3), retries capture a stack runtime by reference (N8), the Scheduler timer can fire after atexit destroys it (N9), and the signal handler locks a mutex (F12).

  • P2

    Framework tests never run.

    make test loops only 15 concrete binaries. The 13 framework test programs are not in any target. Commit 13689e3 changed DirMonitor with zero automated coverage. F7

  • P2

    Nothing on the wire is authenticated.

    The minion answers any datagram and caches its source as the master's reply address. UUIDs are counter + time + pid + IP, so they are guessable. Fine for a trusted LAN demo, not for the stated home/IoT direction. F10

2. Bug catalog

Every open finding, ordered by severity. Each card says what goes wrong, gives a concrete scenario, and names the fix. Click a card's details for the test that would pin it.

P1correctness or data-integrity risk on a normal path P2needs specific timing, config, or a long-running process P3latent, hygiene, or documentation

P1: fix before anything else

P1 N1

A mirrored write can ack the kernel before its second replica is ever sent

What goes wrong. Children are registered and sent one at a time in a loop on a pool worker. Completion runs on the reactor thread and fires as soon as the child set is empty. If child 1's reply arrives while the worker is between iterations, the parent completes with one child, the kernel gets OK, and iteration 2 throws because the parent no longer exists.

The code, as it is today

concrete/master/src/MasterCommands.cpp:280-303 and MasterRuntime.cpp:287-307

The interleaving that breaks it

Repro scenario

Three minions, fio randwrite with more in-flight requests than cores so workers get preempted. Watch for "parent request is not active" in the log while the kernel reports success.

Impact

Silent partial write on the happy-path RAID10 write. For cross-stripe reads: half the data and a spurious EIO.

Fix

Register the whole child set under the lock first, then send. Or declare the expected count in StartRequest and make readiness "all registered AND set empty". See optimization D.

Tests that would pin it
  • Fake proxy that invokes the completion callback synchronously inside SendWriteRequest; assert both operations are sent and the request completes exactly once.
  • Same for a two-segment read; assert the full payload.
  • Stress: many two-child writes under a multi-worker pool with randomized reply delays, under ThreadSanitizer.
P1 F4 + N10

Overlapping writes can land in any order, and a retransmit can resurrect old data

What goes wrong. The kernel sends W1 then W2 to the same offset. Nothing between the NBD socket and the minion's pwrite preserves that order. There are five independent places they can swap, and a sixth failure that needs no concurrency at all.

Repro scenario

fio --rw=randwrite --verify=crc32c against the mounted device with tc netem loss 5%. The verify pass will find blocks holding an older generation.

Impact

Persisted bytes depend on scheduling and packet arrival, not on kernel order. A read overlapping a write can return torn or pre-write data. The read-retry issue in known-issues.md is the same defect seen from the read side.

Fix

A RangeSequencer owned by MasterRuntime: Submit(offset, len, exclusive, dispatch) runs now if the range is free, else parks FIFO. Plus a per-range epoch in the wire header so a stale retransmit is dropped by the minion. See optimization A.

Tests that would pin it
  • RangeSequencer unit tests: full overlap, partial overlap, adjacency, shared readers vs exclusive writer.
  • Master-level test with a recording fake proxy: minion-visible apply order equals NBD arrival order under a multi-worker pool.
  • Retransmit-resurrection test: drop W1, complete W2, fire the retry, assert the minion rejects W1.
  • MinionStorageBackend concurrent overlapping-write tear test.

P2: real defects that need timing, config, or uptime to bite

P2N2

Failover is dead code: nothing ever marks a node down

What goes wrong. NodeInfo::active is set true at RegisterNode and never changes. SetNodeActive, SetNodeHealth, and SendHeartbeatRequest have no non-test callers (re-checked with grep today). So every if (segment.primary.active) is permanently true and the mirror branch in SelectReadTarget is unreachable. Separately, out_of_sync is written but read selection never consults it, so a recovered stale primary would serve old data as OK.

Repro scenario

Start the 3-minion demo, write a file, kill -9 minion 1, read the file. Expected: served from minion 2's mirror. Actual: 10 retries, then EIO on every block whose primary was minion 1.

Impact

A single node failure takes down the whole device, contradicting the degraded-mode claim in system-overview.md. The README is honest about this ("what is missing is the detector").

Fix

A scheduled heartbeat per node registered with ResponseManager; on timeout call SetNodeActive(false). Make target selection treat out-of-sync replicas as read-ineligible. This is roadmap milestone 16 pulled forward.

Tests that would pin it
  • Mark a primary inactive, assert reads resolve to the mirror.
  • Heartbeat timeout flips active to false.
  • An out-of-sync primary is not chosen for reads.
  • E2E: kill a minion mid-run, device keeps serving.
P2F7

make test never runs the 13 framework tests

Example. Verified today: test: concrete-tests loops $(CONCRETE_TEST_BINS) only. ThreadPoolTest, ReactorTest, DirMonitorTest, SchedulerTest and nine others exist but no target names them. Commit 13689e3 changed DirMonitor.cpp with zero coverage.

Fix. Add FRAMEWORK_TEST_SRCS and a framework-tests target; make test and all depend on it. Run DirMonitorTest / DllLoaderTest from framework/ because they build a plugin via relative paths.

P2F8

Runtime is a global pointer with no mutex, cleared before the pool stops

Example. MasterRuntime.cpp:465-485: g_activeRuntime is a plain pointer written by main and read by pool workers. MasterNBDMain calls ClearActiveMasterRuntime() right after framework.Run() returns, but the pool stops later in ~Framework. A worker mid-command throws "No active MasterRuntime", the catch swallows it, and the NBD reply is never sent. The kernel hangs on that request.

Fix. Bind the runtime into the command creator (optimization C). Deletes both globals.

P2F10 + N5

No authenticity or freshness on the wire; minion trusts any source

Example. MasterProxy::GetTask on the minion does no source check and caches whatever address the datagram came from as the master reply address (MasterProxy.cpp:136-158, confirmed). On the master, a spoofed READ_RESP from the minion's IP:port with a guessed UUID (counter + seconds + pid + IP) completes an in-flight read with attacker data.

Fix (tiered). Now: a master-endpoint source check on the minion mirroring IsExpectedEndpoint. Later: per-node keys, HMAC per datagram, per-node sequence with a replay window. README already documents the trusted-LAN assumption.

P2F12

Ctrl-C can deadlock the master with /dev/nbd0 still attached

Example. OnSignal calls RequestFrameworkStop(), which takes a non-recursive mutex the main thread also holds inside Framework::Run(). A SIGINT delivered inside that window deadlocks in pthread_mutex_lock. Only SIGKILL exits, and kernel block I/O on the device hangs. The handler can also new a Handleton on first touch and writes a plain bool.

Fix. Handler does only write() to the stop pipe published in an atomic<int>. Or block signals and register a signalfd in the reactor. See optimization F.

P2N3

~Framework dlcloses plugins before the pool drains

Example. Confirmed in Framework.cpp:189-216: delete m_pluginLoader (which dlcloses every .so) happens before Handleton<ThreadPool>::GetInstance()->Stop(). A worker still executing a plugin command jumps into unmapped code. Factory entries for the plugin's keys are never removed either.

Fix. Stop and join the pool first, then unload. Remove factory entries on unload.

P2N6

Disconnect can hang forever or leave a zombie NBD child

Example. NBDCommunicator::Disconnect ignores the NBD_DISCONNECT ioctl result, then does an unbounded waitpid with no EINTR retry and clears m_childPid unconditionally. If the ioctl silently fails the destructor blocks forever. If a signal interrupts, the child is never reaped.

Fix. Check the ioctl, loop on EINTR, clear the pid only after reaping, bounded wait with SIGKILL fallback.

P2N7

Failed multi-child requests leak sibling state forever

Example. When child A fails, CompleteRequestIfReady erases only the parent. Sibling B stays in m_childToParent and in ResponseManager. The common cause is a dead minion whose siblings never answer, so the entries never self-heal. Memory grows with every failed mirrored write during an outage.

Fix. Route the failure path through the same teardown helper AbortRequest already uses.

P2N8 + N14

A pending retry fires on a destroyed MasterRuntime

Example. Confirmed in MakeRetryParams: the action captures [&runtime, parent_request_id]. MasterRuntime is a stack object in RunMasterNBD; the Scheduler singleton outlives it. A retry armed at shutdown calls RetransmitPendingChildren on freed memory. Root cause: AsyncInjection owns itself (delete this) and has no cancel handle (N14).

Fix. Return an owning handle from scheduling; cancel all pending retries in ~MasterRuntime.

P2N9

Scheduler timer thread can run after atexit destroyed the Scheduler

Example. Scheduler is a Singleton deleted via std::atexit. Its SIGEV_THREAD callback calls GetInstance()->HandleTimer(), but GetInstance returns a cached static pointer that is never re-read, so after deletion it dangles. timer_delete does not stop an already-triggered notification thread.

Fix. Owned shutdown that disarms and joins before exit; GetInstance should return m_instance so a destroyed singleton reads null.

P2N4

select() with fd >= 1024 corrupts the stack

Example. LinuxFdListener::Listen checks only fd < 0, then FD_SETs it. A long-running master that churns through sockets past fd 1023 writes past the stack fd_set. Latent today, a hard ceiling for the intended always-on deployment.

Fix. Reject fd >= FD_SETSIZE now; migrate to poll or epoll (see optimization G).

P2F2 residual

ReadAll can stall the reactor; payload length is uncapped

Example. After readiness, ReadAll blocks the reactor thread with no timeout. If the kernel-side child dies mid-message the reactor stalls. out.payload.resize(out.length) trusts the 32-bit kernel length with no sanity cap.

Fix. Cap length against the configured block size; bounded read with a poll timeout.

3. Roadmap and next steps

Two documents disagree about what comes next. The roadmap and step-order say "persistent metadata". The July review says "fix N1, F4, N2 first". This section shows both and recommends a merged order.

3.1 Where the roadmap stands

  • 1-3 Docs, wire protocol, task types
  • 4-5 Minion transport + storage
  • 6-7 Master transport + correlation
  • 8-10 Commands, sim, metadata v1
  • 11-12 RAID10 + degraded v1
  • 13-14 Real NBD + retransmit
  • 15 Persistent metadata
  • Discovery + health

Tension. Milestone 12 "degraded-mode v1" is marked done, but its read-failover branch is unreachable (N2). Milestone 15 would persist out_of_sync state that nothing currently sets correctly. Persisting broken state does not make it less broken.

4. Proposed optimizations

These are structural changes, not micro-optimizations. Each names what it improves and which findings it closes, with before/after code where the change is concrete enough to show.

Target shape of the master after A, C, and D

A

Range-ordering module

closes F4, N10, known-issues read-retry

Improves: overlapping writes apply in NBD arrival order; reads never see a torn or pre-write block; a stale retransmit is dropped. Cost: one new class in MasterRuntime, one header field (epoch), and a small interval lock on the minion. Non-blocking parking, so pool workers never stall.

concrete/master/src/MasterCommands.cpp, write dispatch (sketch)

D

Placement-plan module, and the minimal N1 barrier

closes N1, contains N8 captures, removes x3 policy duplication

Improves: RAIDManager returns a ready-to-dispatch plan with owned proxy handles. The three master commands stop re-deriving primary/mirror/degraded/slice policy. The whole plan is registered atomically before any send, which is the N1 fix. The minimal version below is a same-day change; the full plan module is phase 4.

concrete/master/src/MasterCommands.cpp:281-301 (minimal barrier)

C

Runtime-bound command adapters

closes F8 incl. shutdown drop window; highest testability payoff per line

Improves: commands declare their dependency instead of reading a global; two runtimes can coexist in one process; commands are constructible in a unit test without the install/clear ritual. The framework change is one typedef: creators become std::function<std::unique_ptr<ICommand>()> so the map can capture the runtime.

concrete/master/src/MasterCommands.cpp + MasterRuntime.cpp (sketch)

F

Async-signal-safe stop

closes F12, part of N17

Improves: Ctrl-C can no longer deadlock on the framework mutex or allocate in a handler. The pipe's readability becomes the stop request, so m_stopRequested disappears. Cleanest on Linux is a signalfd registered in the reactor; the write-only handler below is the smaller step.

framework/src/Framework.cpp, RequestFrameworkStop (sketch)

B

One wire-codec seam

closes F9, shrinks F10 surface

Improves: the three decode sites (MasterProxy, MinionProxy, MinionResponseProxy) share one strict decoder that requires exact size and returns either a validated message or a drop reason. Fuzzing and protocol v2 become one-place changes.

concrete/master/src/MinionResponseProxy.cpp, DecodeResponse (sketch)

G

select() to poll()/epoll

closes N4

Before: rebuild an fd_set every iteration, scan for maxFd, hard 1024 ceiling with stack corruption past it. After: a persistent pollfd vector (or an epoll set), no ceiling, no per-call rebuild. Reactor-internal change only; ReactorTest covers it once F7 runs it.

H

Cancellable AsyncInjection

closes N14, enables N8/N9 fixes

Before: delete this on completion, owned by nobody, never cancellable; a never-completing action leaks. After: scheduling returns an owning handle; ~MasterRuntime cancels all pending retries. Also fixes the leak for requests that never complete.

I

Single writev for NBD replies

closes F3 residual

Before: two WriteAll calls under the mutex; a throw between them leaves the stream desynced. After: header and payload in one writev; on any partial write, mark the communicator broken so later replies fail fast instead of corrupting framing. One syscall instead of two per read reply.

J

Collapse Singleton and Handleton

simplification, reduces N9 surface

Before: two character-identical lazy-global mechanisms coexist; Singleton::GetInstance caches a static pointer that dangles after atexit. After: keep Handleton (it survives dlopen boundaries, which the plugin story needs), give it an owned shutdown. Worth a conscious decision given the roll-your-own learning goal, so this is "explore", not "must".

E

Plugin-deployment adapter

closes F5 residual, pairs with N3

Before: Framework subscribes to added and modified events and dlopens immediately; a partial image can be pinned. After: a SubscribeReady fired only on IN_CLOSE_WRITE | IN_MOVED_TO, exception containment, and unload that also removes factory keys. Document rename-based deploys.

K

Minimal transport trust

F10 / N5 first tier

Before: minion answers anyone and redirects replies to the last sender. After (now): configured master endpoint check on the minion, mirroring the master's IsExpectedEndpoint. After (later): per-node key, HMAC over each datagram, per-node sequence with replay window. The header's reserved fields leave room for this without a v2.
